# Sourcever Implementation Plan

**Goal:** Build a runnable Chinese capability explorer and an open-source-ready repository.
**Architecture:** Dependency-free Node HTTP server, browser ES modules, versioned JSON graph. Curated examples work offline. An optional server-side OpenAI-compatible provider handles new needs and returns schema-validated research drafts; no claim of live verification.
**Tech Stack:** Node >=22, HTML/CSS/JavaScript, node:test.

1. Author six public-domain topic datasets with attributed claims, evolution branches, failures, resources, access and frontier hypotheses. Validate IDs, graph edges and URLs.
2. Implement read-only data API and optional model analysis endpoint, with size/time limits, safe static routing and no client-side secrets.
3. Build responsive map explorer: need input, topic selection, interactive evolution graph, reason panel, resources, source map, access eligibility, frontier and downloadable creation briefs.
4. Add README, methodology, data model, access bill, contribution guide, MIT license and portable SKILL.md.
5. Test graph integrity, topic matching, unknown needs, invalid input, provider errors, exports and static server boundaries. Verify desktop/mobile UI in browser if available.

## Scope decisions
The current request selects local workspace implementation and open-source scaffolding. No GitHub repository is published in this pass. Six curated examples are explicitly labeled; optional AI results are unverified drafts. No payments, account system, crawler, or automated application for benefits.

## Visual direction
Ink-blue research atlas with mint-green active routes, a persistent left topic rail, compact query header and a large branching graph. Details are readable beside the map; mobile collapses to stacked panels. The input is always immediately usable.
