# 从需求到能力，而不是从关键词到链接

## 先找不变的任务

“做一个在线文档工具”是产品形态。底层任务是“多人跨地点共同修改和管理信息”。祖先可能包括附件、共享存储与实时编辑；不要把今天的品牌列表误认为历史。

## 解释箭头

每条演化边包含：旧方案的能力、未满足需求、促成条件、新能力和新问题。演化并不必然是替代；本地优先、自托管、托管服务可能长期并存。一个现代产品页只能说明产品能力，不能单独证明路线的起源和因果。

## 保留反例

关闭公告支持“关闭”这一事实，不一定解释完整商业原因。采用率、平台替代或时间太早等解释应分别有证据。没有可靠失败资料时展示资料缺口，不编造故事。

## 来源分层

Original 是已确认的原始发布；Official 是官方确认；Professional 提供专业解释；Community 提供体验；Distribution 负责传播。来源角色不代表 SourceRank 分数。本版不实现评分，也不保证任何入口为最早首发。

## 让资源可行动

Resource 关联 Solution 与官方 Source；Access 记录步骤、费用类型、资格、地域和时间窗口。未知字段显式标为未核验。身份选择仅用于提示可能相关条件，不替代提供方的资格审核。

## 创造前先验证

成熟能力优先复用；正在变化的能力持续关注；未解决方向要写成假设，并设计可观察的验证任务。没有访谈与替代方案比较时，不声称发现市场空白。
