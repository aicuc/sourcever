# 网站搭建

输入：我想快速搭建一个网站

底层需求：把信息或服务发布到网络，让他人可以稳定访问。

> 编辑案例，路线为概括性综合。时间不代表首创；来源页面可能仅支持当前能力。

## 历史路线

### 超文本网页 · 1990s

解决：让文档通过链接公开访问

仍缺少：内容更新需要手动维护

代表：HTML / HTTP

### 动态网站 · 1990s–2000s

解决：按请求生成内容与处理表单

仍缺少：需要维护服务端和数据库

代表：服务端应用

### 内容管理系统 · 2000s 起

解决：让非开发者维护网站内容

仍缺少：插件兼容与维护成本

代表：WordPress

### 静态托管 · 2010s 普及

解决：从代码仓库发布静态页面

仍缺少：动态能力需要外部服务

代表：GitHub Pages

### 组合式网站 · 当代路线

解决：把托管、内容和 API 组合成服务

仍缺少：跨服务权限与数据流更复杂

代表：托管 + API

### AI 辅助建站 · 探索中

解决：缩短从需求到页面的制作过程

仍缺少：生成结果仍需验收与维护

代表：生成式开发工作流

## 为什么会发生跃迁

- **超文本网页 → 动态网站**：服务端处理使页面从文档变成应用。新问题：需要维护服务端和数据库。

- **动态网站 → 内容管理系统**：内容与模板分离降低编辑门槛。新问题：插件兼容与维护成本。

- **动态网站 → 静态托管**：版本管理与自动部署减少手工发布。新问题：动态能力需要外部服务。

- **内容管理系统 → 组合式网站**：API 分工让成熟能力可被组合。新问题：跨服务权限与数据流更复杂。

- **静态托管 → 组合式网站**：API 分工让成熟能力可被组合。新问题：跨服务权限与数据流更复杂。

- **组合式网站 → AI 辅助建站**：生成模型降低原型制作门槛，但可靠性仍需验证。新问题：生成结果仍需验收与维护。

## 失败 / 停止路线

### Adobe Flash Player · 2020 · 结束更新与分发

为浏览器带来丰富互动内容。 在早期 Web 提供统一多媒体运行环境。

结果：主流 Web 内容迁向开放格式。 Adobe 官方指出 HTML5、WebGL 等开放标准成熟。

启示：这更接近平台原生能力替代；不能把曾经有效的技术路线简单归为错误。

## 可复用资源

- [WordPress](https://wordpress.org/)：下载开源软件并选择主机；自行承担托管成本。 条件：遵循服务条款或开源许可证；部署和附加服务可能收费。

- [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)：注册 GitHub，创建仓库，在 Pages 设置中选择发布来源。 条件：遵循服务条款或开源许可证；部署和附加服务可能收费。
